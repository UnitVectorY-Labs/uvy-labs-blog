repver v0.6.4 was released on 2026-10-24. This release improves observability of the Git workflow without changing how replacements work. When repver runs with Git actions enabled, successful steps are now confirmed in normal output, making it easy to verify that branches, commits, pushes and pull requests completed as expected.

## What's new

The primary change is reporting completed Git actions in normal command output. Previously, successful Git steps were only visible with `--debug`, leaving users unsure whether a run finished correctly and encouraging unsafe retries.

Starting in v0.6.4, confirmation lines are written to stderr after each successful step:
- Created branch
- Committed with short SHA and message
- Pushed remote/branch
- Created pull request with URL
- Switched to original branch
- Deleted local branch

File diffs remain on stdout between branch creation and commit, preserving existing tooling expectations. Push failures now include Git diagnostics and report the commit SHA and branch left behind. Dry-run mode is unchanged and emits no action confirmations.

Documentation in `docs/COMMAND.md` was updated with examples for the new output ordering and error handling.

## Why it matters

For users automating version bumps and releases with `.repver` configurations, visibility is reliability. Confirmations on stderr give immediate feedback that the full Git flow executed without requiring debug flags or parsing stdout. Scripts that consume diff output continue to work because confirmations are separated to stderr.

The release also includes operational improvements that strengthen reliability: test coverage was expanded across internal packages with new unit and CLI integration tests, CI workflows were updated to Go 1.27.2, and weekly OSV-Scanner vulnerability scans were added alongside routine dependency updates. These changes do not affect CLI behavior but support a more stable foundation.
